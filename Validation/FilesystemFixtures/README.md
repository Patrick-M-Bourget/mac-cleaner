# Genuine owned-volume scanner fixtures

This opt-in qualification harness exercises the public `FolderScanner.scan` seam against a genuine mounted HFS+ image. It is not app functionality and is not part of ordinary package tests. It refuses to provision images unless both GitHub Actions and its `github-hosted` runner environment are declared. Do not bypass that guard on a personal Mac or persistent runner.

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift build -c release --package-path Validation/FilesystemFixtures
python3 Validation/FilesystemFixtures/run.py --ci-owned-images --executable Validation/FilesystemFixtures/.build/release/FilesystemFixtures --reports "$RUNNER_TEMP/filesystem-fixture-reports"
```

The Python orchestrator creates a private UUID temporary directory, requires 512 MiB free headroom and creates one 64 MiB HFS+ image. It requests an exact mountpoint beneath its root with no Finder browsing or auto-open. It saves the returned attach plist, obtains the device only from its exact mounted entity, and independently checks `hdiutil info -plist` associates that device with its owned image. Native `st_dev` must differ between parent and mounted scope. It creates only a known 17-byte sentinel and a 1 MiB repeated-byte compression source, and copies the latter onto the mounted volume with system `ditto --hfsCompression`.

The Swift executable observes public scan results:

- Scanning the parent reports `.differentVolume`, descends into no mounted descendants and exposes unknown complete totals.
- Explicitly scanning the owned mounted subfolder observes the known sentinel.
- The compressed candidate preserves its known 1 MiB logical length. Qualification requires actual native `UF_COMPRESSED` and a known smaller allocated length. If the filesystem/tool declines compression, the report explicitly says unsupported; an ordinary file is never labeled positively compressed.
- After the orchestrator detaches the exact verified device, the former subfolder is unavailable and reports no complete total. This covers disconnected scope recheck, not removal during an in-flight provider call.

`finally` handles ordinary failures and SIGINT/SIGTERM by revalidating the exact image/device mapping before a normal non-forced detach. It removes the owned root only after confirmed detach and an unmounted mountpoint. Unknown mappings, ambiguous attach results, timeouts and detach failures preserve the root rather than guessing a device or recursively traversing a possible mount. SIGKILL/runner termination cannot guarantee cleanup; ephemeral runner disposal is the final boundary. No elevation, real-volume changes, user storage, cloud content, Finder launch or OS preference changes are used. HFS+ coverage does not certify every APFS/external/provider behavior.

Artifacts: `attach.plist`, `mounted.json`, `unmounted.json`, and `lifecycle.json`. A zero exit status alone does **not** certify positive compression: inspect the `compression` field, and verify `detached` and `ownedRootRemoved`. Failed processes leave lifecycle diagnostics and fail the job. Runtime reports must be linked to their exact source/run before closing any qualification gate.

## Research and local validation

Apple's installed `/usr/share/man/man1/hdiutil.1` documents machine-readable `-plist`, exact `-mountpoint`, `-nobrowse`, `-noautoopen` and normal device detach. Apple's installed `/usr/share/man/man1/ditto.1` documents compression only when appropriate on supporting HFS+/APFS filesystems. Those manuals were read on macOS 27.0.1; their original bytes and SHA-256 hashes are retained in the external task notes. [Apple's published stat header](https://github.com/apple/darwin-xnu/blob/main/bsd/sys/stat.h) defines `UF_COMPRESSED` and the 512-byte `stat` block unit. Neither `st_blocks` nor allocation observations are exclusive reclaimable-byte claims.

Local Debug compilation with Xcode 27.1 passed, and the orchestrator's personal-host refusal was verified before any root/report directory or image could be created. No image creation, attachment, compression or detachment has run on the personal host. The final hosted run below qualifies the genuine HFS+ boundary and positive compression checks on that runner; it does not close all of #34. Existing reference 512 GB hardware, cloud non-hydration and non-returning-provider gates remain open.

The first hosted attempt ([40002281606](https://github.com/Patrick-M-Bourget/mac-cleaner/actions/runs/40002281606), source `c522750`) failed before image creation: blank image creation does not accept `-format UDRW` on Xcode 26.6/macOS 26.6.2. Its lifecycle report confirms the owned temporary root was removed and no attach occurred. The corrected command uses `-type UDIF`, Apple's documented blank read/write image type; `-format` is for images populated from a source folder/device. `hdiutil create -help` and the installed manual were checked without creating or attaching an image locally. This changes fixture provisioning only, with scanner assertions and device verification unchanged. The exact mounted `/dev/diskNs…` node returned by attach remains the normal detach target, as the manual accepts a device node or mountpoint and detaches its associated image through Disk Arbitration; its image association is revalidated immediately before detach.

The second hosted attempt ([40002795302](https://github.com/Patrick-M-Bourget/mac-cleaner/actions/runs/40002795302), source `8af9a58`) successfully provisioned the genuine image and passed the parent boundary assertions, but failed the combined explicit-scope/sentinel assertion. Its lifecycle report confirms exact-device detach and owned-root removal both succeeded. The original harness did not persist scan observations before asserting, so that checkpoint did not identify whether coverage, filename/URL representation or observed logical length caused the disagreement. The runner now writes public `ScanResult` scope, completeness, observation metadata and issue reasons, plus native metadata for its two known fixture files, before semantic assertions. It also records each mounted check independently. These are synthetic fixture paths only. Assertions and production scanner code were unchanged at that diagnostic checkpoint.

The diagnostic run ([40004053906](https://github.com/Patrick-M-Bourget/mac-cleaner/actions/runs/40004053906), source `169a255`) identified a fixture expectation bug: the explicit scope was represented as `/var/…`, while its two observed files used `/private/var/…`. Public results were complete with exactly 1,048,593 logical bytes; the sentinel was 17 bytes and the compressed file was 1,048,576 logical / 8,192 allocated bytes with native `UF_COMPRESSED`. Literal URL equality therefore rejected correct scanner observations. The corrected fixture compares both canonical paths **and** exact native device/inode identities; it retains file-kind and literal logical/allocation assertions. No production scanner behavior changed. A focused public scanner test now scans the same owned 17-byte file through both native temporary-path aliases and verifies complete totals and the exact resource identity. The diagnostic failure alone is not labeled a complete harness pass; the final corrected mounted/unmounted sequence is recorded below.

The temporary-path alias regression passed locally (1/1, 0.029 seconds) with Xcode 27.1, and the revised fixture executable compiled. No local image was created or mounted.

Containment checks also canonicalize **both** the mount boundary and each observed/issue path into path components. The mount row itself is permitted, while any additional component beneath that canonical boundary fails the run. This avoids treating `/private/var/…` descendants as outside a `/var/…` prefix. The report retains canonical mount components and any rejected descendant paths so the negative assertion is reviewable across aliases; exact fixture-file identity checks remain separate.

## Final hosted qualification

[Run 40005065584](https://github.com/Patrick-M-Bourget/mac-cleaner/actions/runs/40005065584), exact source `9ef1f06042b8ec4c771b7bde7b184846e3be5d9a`, passed on macOS 26.6.2 (25G83), Xcode 26.6, using the manual `filesystem` selection. The 70-second job compiled Release and ran only this fixture; it did not rerun UI journeys or the million-entry benchmark. All eleven independent mounted checks were true, including the actual sentinel descendant positive control and the canonical no-descendants assertion. Parent and mounted native devices differed. Parent coverage was partial with `.differentVolume` and unknown complete total; the explicit mounted scope was complete with exactly 1,048,593 logical bytes. The sentinel retained 17 bytes; the genuinely compressed file had `UF_COMPRESSED` (flags 32), 1,048,576 logical bytes and 8,192 allocated bytes. The normal exact-device detach succeeded. Rechecking the former mounted subfolder returned `.locationUnavailable`, no observations and unknown complete total. Both detach and owned-root removal were confirmed in lifecycle evidence.

The [raw source/run/hash manifest](../../docs/validation/benchmarks/filesystem-manifest.json) links the final JSON and attach plist plus historical failed-attempt JSON. All paths in those reports belong to the hosted synthetic fixture. The earlier successful run 40004871158 used source `7a38a709` before strengthened canonical containment and is not substituted for this final proof. The HFS+ boundary, explicit mounted scope, positive native compression and disconnected recheck are qualified on this runner. APFS mount variants, removal during in-flight blocked I/O, cloud/provider non-hydration, non-returning-I/O cancellation and the specified 512 GB reference environment remain open; #34 and release qualification remain open.
