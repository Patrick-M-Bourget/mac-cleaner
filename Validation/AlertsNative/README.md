# Genuine native alert authorization and window lifecycle

Manual GitHub Actions suite: `alerts-native`. This is one bounded experiment on a fresh GitHub-hosted macOS VM, separate from ordinary `alerts` policy/on-demand UI checks. It needs no distribution credentials or M8 signing work.

`prepare.py` refuses ordinary/local/self-hosted executions before writing evidence or launching anything. It verifies manual event/suite, hosted identity, non-root runner user, source commit, absent normal app state/preferences, >2 GB available headroom and the actual ad-hoc app signature. The generated `StillUITests.EnvironmentVariables` dictionary is the observed XCTest runner interface; guards are injected there explicitly, not assumed to pass from shell variables. The test independently validates those guards, an owned 0700 report directory and fresh normal app state before launch. Existing disposable-test authorization protection remains unchanged; this dedicated job uses the VM's normal fresh app-owned state instead.

The UI test starts off, explicitly selects a 1 GB threshold using real capacity, then chooses opt-in once. It discovers any running notification UI's actual bundle identifier from its observed display name. It clicks only an exact visible Allow control in a window also identifying Still and an exact refusal control. There is no generic Allow click, interruption monitor, guessed system app bundle ID, permission reset, TCC database read/write, sudo, profile/defaults/Settings hack, re-signing or retry loop. Permission UI discovery is bounded to 15 seconds; if no actionable expected prompt or confirmed authorized monitoring is available, screenshot/tree/status evidence is retained and the test reports unsupported rather than forcing access.

If native authorization succeeds, the journey verifies a valid monitoring status, menu-bar presence, close-window process retention, public Show Still reopening, explicit Quit, automatic saved monitoring restoration from Overview **before** revisiting Settings, disable and on-demand exit. No folders are chosen and History must remain empty. Start at Login is never toggled. The VM owns the grant and app state; its disposal ends the experiment. Cleanup only terminates the exact launched test app.

Evidence artifact `native-alert-qualification` contains the `.xcresult`, source/environment/signature manifest and `journey.json`. `unsupported-native-authorization`, missing journey output, skipped tests or a successful compile are not a native feature pass. A passing journey qualifies only the recorded hosted OS/architecture and these interactions. It does not certify real notification delivery/banner visibility, denied/revoked permission transitions, 15-minute timing, sleep/wake, minimum OS, Intel or SMAppService/login registration. Acceptance is distinct from display; no synthetic low-space injection or disk filling is used.

Local verification is limited to build-for-testing compilation, plist/workflow structure and the refusal guard; never execute the opted-in UI journey on a personal host.
