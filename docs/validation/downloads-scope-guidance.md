## Behavior and design

The shared `CleanupScopeNotice` appears in Overview, folder inspection, empty plan and live plan. It explains: “Cleanup currently supports files in Downloads only. Other folders are inspection only.” Its native “Choose Downloads…” button opens `NSOpenPanel` at Downloads. Only the user's confirmation starts metadata inspection; Cancel preserves the current view, observations and choices. Another folder may still be chosen for inspection. The chooser repeats the restriction. The shortcut neither selects files nor approves cleanup; eligibility and execution safety checks are unchanged.

The notice composes existing status typography, spacing and a native button. Enabled/disabled examples are in the Debug gallery. Review uses the actual shared disabled control. Sixteen [original captures and their source/run/hash manifest](../visual/downloads-scope-guidance/manifest.json) cover four states in Light/Dark at hosted initial **1024 × 640** and minimum **900 × 640** sizes. The contact sheet and representative full-size captures were reviewed: readable scope explanation, visible shortcut, correct theme surfaces, reachable fixed action strip and no changed outer bounds. The wider 1120 × 760 desktop preset remains separate from this constrained-host evidence.
