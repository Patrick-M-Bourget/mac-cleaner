## Data contract

Only explicit folder-picker scans are candidates. A metadata-only token captures canonical scope identity, root resource identity, volume UUID and root permissions/ownership before scanning. Completion rechecks that identity and rejects cached timestamps. Compatible snapshots require the same scope/root/volume, readable-coverage policy, enumeration rules, exclusions and classification version. A denied/revoked/partial/cancelled scan or package/other unmeasured content cannot establish a completed baseline. More than 128 top-level folder groups remains unknown, avoiding silent regrouping at the cap.

Complete snapshots persist hashed scope/group identifiers, scope/folder labels, observation time and logical folder/category totals. File contents, per-file paths, filenames, hashes and writer attribution are not stored. Folder labels remain sensitive local metadata. Logical sizes count hardlinked resources once under the first observed path; alias changes may redistribute group totals without changing the net total. Categories are deterministic file-type groups (Documents, Media, Archives and installers, Other files), independent of cleanup eligibility. Folder and category dimensions describe the same bytes and are never summed together. These are observed logical changes, not allocated, exclusive or reclaimable-space estimates.

The selected observation compares with the latest preceding completed observation of its scope, even when other scopes were scanned between them. A differing fingerprint shows **Coverage changed**, with no numeric growth claim. The UI distinguishes first observation, missing/expired baseline, explicitly cleared history and unknown coverage. Completed comparisons show both interval endpoints, scope, completeness and folder/category net changes. This is an observation interval, not evidence about which process or person caused a change.

## Persistence and retention

`GrowthHistoryStore` owns only `Growth/aggregates-v1.json` beneath the shared local app-state root. Reads and writes enforce rolling 90-day retention, at most 30 completed snapshots and a 250,000,000-byte cap. Data is aggregate bounded (512 groups, bounded labels); JSON writes are atomic. Symlinked storage and malformed archives fail closed. Oversize observations remain unknown. Normal state is local Application Support; native tests bind the shared identity-checked owned temporary root and never write personal baseline history.

`clearCompletedHistory()` removes only aggregate baselines and preserves an explicit cleared marker. The native model exposes the matching clear hook for future History work. A separate `resetHistory()` hook removes only the known aggregate file and returns to first-baseline state; it preserves unrelated unresolved records and invalidates pending native history attempts. Neither retention nor clearing opens/enumerates/deletes cleanup journals. Unresolved recovery authority remains under its separate journal contract and is never retention-evicted.
